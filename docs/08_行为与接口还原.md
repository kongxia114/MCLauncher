## 二、启动流程【推断，基于字符串顺序】

```
启动
 ├─ 读 mclauncher.cfg → [MClauncherNEW]
 │    · 第一次运行=真 → 弹出"请完成以下设置"，引导选 Java
 ├─ 检查 Java：配置里的 java路径 是否有效（文件存在）
 │    · 无效 → 提示"没有找到java路径,请手动指定javaw.exe"
 │    · 未安装 → 提示"没有安装过java可以选择自动下载按钮"
 │         └─ IsWow64Process 判断 64 位 → 下载 java64 / java32
 │              → %TEMP%\mctemp\java.temp.exe → 静默安装
 ├─ 枚举 .minecraft\versions\* 填充"游戏列表"
 │    · 若发现旧版布局 .minecraft\bin\minecraft.jar → "当前目录发现旧版本游戏,开始导入"
 ├─ 检查自身更新（checkversion）
 │    · 有新版本 → "发现MCLauncher新版本" [立即更新] [稍后更新]
 ├─ 加载皮肤 \bgskin\*.jpg（缺失则下载 bgskin.zip）
 └─ 进入主界面
```

## 三、配置文件 `mclauncher.cfg`

INI 格式，节名 `[MClauncherNEW]`，与 exe 同目录【实证：样例文件】。

| 键 | 样例值 | 含义 |
|---|---|---|
| `游戏名字` | `1234` | 当前选中的版本/整合包名 |
| `java路径` | `C:\Program Files\Java\jre1.8.0_481\bin\javaw.exe` | javaw 全路径 |
| `最大内存` | `1024` | 单位 MB，拼进 `-Xmx` |
| `第一次运行` | `假` | 首启引导标记 |
| `内存设置方式` | `手动` | 自动/手动（自动按物理内存比例） |
| `调试` | `真` | 调试模式：改用 java.exe 并生成 `输出日志.txt` |
| `启动器背景方式` | `默认皮肤` | 背景图模式，另有"随机皮肤" |
| `正版登录` | `假` | 是否使用正版账号启动 |

相关文案：`最大内存`(0x0B720A)、`java路径`(0x0B7224)、`内存设置方式`(0x0B9DBB)、`调试模式`(0x0BA64B)、`输出日志.txt`(0x0BA387)、`开启调试模式将以java.exe启动minecraft,并且在启动器目录生成输出日志.txt`(0x0BA7E0)。

## 五、版本管理

支持两代目录结构：

**旧版（≤1.5）**
```
.minecraft\bin\minecraft.jar
.minecraft\bin\jinput.jar
.minecraft\bin\lwjgl.jar
.minecraft\bin\lwjgl_util.jar
.minecraft\bin\natives\
```

**新版（1.6+）**
```
.minecraft\versions\<版本名>\<版本名>.json
.minecraft\versions\<版本名>\<版本名>.jar
.minecraft\assets\indexes\<index>.json
.minecraft\assets\objects\<前2位>\<hash>
.minecraft\libraries\...
.minecraft\natives\
```

解析的 JSON 字段【实证】：`id`、`type`（release/snapshot）、`releaseTime`、`mainClass`、`minecraftArguments`、`libraries[].name`、`libraries[].url`、`assets`、`assets_index_name`、`version`。

旧版导入【实证】：`当前目录发现旧版本游戏,开始导入`、`导入旧版本`、`输入版本名称`、`保存到.minecraft\versions\版本名称\`、`已经导入，删除本文件重新导入`。

## 七、正版登录（Yggdrasil）

**认证请求**【实证】

```
POST https://authserver.mojang.com/authenticate
Content-Type: application/json; charset=UTF-8
User-Agent: Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.0)   ← 易语言默认 UA

{"agent":{"name":"Minecraft","version":1},
 "username":"<邮箱>",
 "password":"<密码>",
 "requestUser":true}
```

其中 `clientToken` 写死为 `88888888-8888-8888-8888-888888888888`【实证：0x0BA0xx 附近】。

**JSON 处理**：通过 `MSScriptControl.ScriptControl` + `JavaScript` 引擎，用注入的 JS 片段做 parse/stringify【实证：0x100BB8、0x1037E4–0x103945 一整段 JS】。这也解释了为什么导入表里没有 JSON 库。

**与官方启动器打通**【推断，证据充分】：
字符串里有一整套 `launcher_profiles.json` 的字段路径：

| 字符串 | 偏移 |
|---|---|
| `\launcher_profiles.json` / `\.minecraft\launcher_profiles.json` | 0x0B7232 / 0x0B7257 |
| `accessToken` | 0x0B9E3E |
| `selectedProfile.id` | 0x0B9E4A |
| `selectedProfile.name` | 0x0B9E5D |
| `user.properties[0].name` / `.value` | 0x0B9E72 / 0x0B9E9E |
| `twitch_access_token` | 0x0B9E8A |
| `{"twitch_access_token":["替换"]}` | 0x0B9EBC |
| `appdata`、`\mclauncher\login` | 0x0B9E24 / 0x0B9E2C |

→ 程序会读写 `%APPDATA%\.minecraft\launcher_profiles.json` 的 `authenticationDatabase`，
把登录态与官方启动器共享/导入，本地另存一份到 `\mclauncher\login`【推断】。

> 这也意味着：**它保存的 accessToken 是明文的**，换机器/共享配置时要留意。

## 八、启动游戏（最核心的一段）

### 8.1 新版（1.6+，走版本 JSON）

拼接模板【实证，字符串被拆成多段】：

```
<javaw或java> -Xincgc -Xmx<最大内存>m
   -Dfml.ignoreInvalidMinecraftCertificates=true
   -Dfml.ignorePatchDiscrepancies=true
   -Djava.library.path=".minecraft\natives"
   -cp "<libraries 全路径;版本.jar>"
   <mainClass>
   <minecraftArguments 逐项替换 ${...}>
```

`${...}` 变量表【实证】：

| 变量 | 含义 |
|---|---|
| `${auth_player_name}` | 玩家名 |
| `${auth_access_token}` | 正版 token |
| `${auth_uuid}` | 玩家 UUID |
| `${auth_session}` | session id（`token:uuid`） |
| `${version_name}` | 版本名 |
| `${game_directory}` | 游戏目录 |
| `${assets_root}` | assets 根 |
| `${game_assets}` | 虚拟资源目录 |
| `${assets_index_name}` | 资源索引名 |
| `${user_type}` | `legacy` / `mojang` |
| `${user_properties}` | 用户属性 JSON |

### 8.2 旧版（≤1.5）

```
javaw.exe -Xincgc -Xmx<内存>m -cp ".minecraft\bin\minecraft.jar;.minecraft\bin\lwjgl.jar;.minecraft\bin\lwjgl_util.jar;.minecraft\bin\jinput.jar"
    -Djava.library.path=".minecraft\bin\natives" net.minecraft.client.Minecraft <用户名> <session>
```

证据字符串：`\minecraft.jar;`、`\lwjgl.jar;`、`\lwjgl_util.jar;`、`\jinput.jar;" -Djava.library.path="`、`\natives" net.minecraft.client.Minecraft `。

### 8.3 其它细节

- 调试模式改用 `java.exe` 并把 stdout 重定向到 `输出日志.txt`（`>输出日志.txt`）【实证】。
- 调试模式并不直接重定向，而是**临时生成一个批处理**再执行【实证 0x0BA377，执行方式推断】：

  ```bat
  <java 启动命令> >输出日志.txt
  pause
  del %0
  ```

  文件名为 `mclauncher.bat`（字符串里带前导反斜杠），运行完自删除（`del %0`）。
  所以只要开一次调试模式，启动器目录里就能直接看到**完整的 java 命令行**——这是最省事的抓取方式。
- 进程创建用 `CreateProcessA`【实证：导入表】。

> **想拿到完整命令行，不用反编译**：x32dbg 在 `CreateProcessA` 下断即可，见 `07` 第四节。

## 九、自更新

```
GET http://updatemc.mcsky.net//launchernew/checkversion   → 返回最新版本号
   ├─ 版本相同 → 继续
   └─ 有新版本 → 弹窗 "发现MCLauncher新版本" [立即更新][稍后更新]
         └─ 下载 update.exe → 写 update.bat → 运行
              update.bat: 等待退出 → ren update.exe <本程序名> → 删除 bat → 重启
```

证据：`latestversion`(0x0FC232)、`发现MCLauncher新版本`(0x0FC240)、`立即更新`(0x0FC25E)、`稍后更新`(0x0FC255)、`更新launcher版本`(0x0FC280)、`\update.exe`(0x0FC291)、`\update.bat`(0x0FC29D)、`ren update.exe`。

另有一个 `http://launcher.sinaapp.com/m/?post=2` 的短链跳转，疑似公告/广告位【实证，用途推断】。
