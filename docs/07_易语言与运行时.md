# 语言判定与运行时分析

## 一、结论：易语言 5.x，静态编译模式

这不是"猜"的，下面每条都可以在导出的字符串表里对上。

| # | 证据 | 位置 / 值 | 说明 |
|---|---|---|---|
| 1 | 版本资源 | `CompanyName=忘却的旋律`、`ProductName=MCLauncher`、`FileVersion=5.31.0.0` | 见 `资源/版本信息.txt` |
| 2 | `ATL.DLL` 序数导入 | `#47 #11 #42 #10`（无函数名） | 易语言静态运行库的固定特征；正常 C++ 程序不会这样导入 ATL |
| 3 | `OLEPRO32.DLL` 序数导入 | `#251` | 同上，易语言运行库的 OLE 图片/对象支持 |
| 4 | 运行库错误文案 | `0x106234` 所提供参数的数据类型不符合要求<br>`0x106384` 数组成员引用下标必须大于等于1<br>`0x106338` 调用DLL命令后发现堆栈错误，通常是DLL参数数目不正确 | **这些是易语言 krnln 运行库的报错原文**，被静态链进了 exe |
| 5 | zlib 错误文案 | `0x1065D8` incompatible version … `0x106630` file error | 易语言压缩支持库（eCompress）内置的 zlib |
| 6 | 专属标记 | `0x1064A0` `blackmoon` | 易语言运行库内部标记串 |
| 7 | 界面库类名 | `0x0B75F7` `Ex_DirectUI_MsgBox`、`0x0B9864` `Ex_DirectUI_Host`、`0x0B9875` `Ex_DirectUI_Sub`、`0x0B9885` `Ex_DirectUI_Act`、`0x0B9895` `Ex_DirectUI_Event`、`0x103EC6` `Ex_DirectUI_Combox`、`0x104DCA` `Ex_DirectUI_Menu` | **Ex_DirectUI** 是易语言社区著名的 DirectUI 界面库（自绘窗口/控件） |
| 8 | 字符串编码 | 全部 GBK，NUL 结尾，集中在 `.data` 0xAA000–0x10B000 | 易语言常量池的标准形态：无长度前缀、无引用表、连续存放 |
| 9 | 编译器 | PE 链接器版本 6.0、镜像基址 0x400000、**无重定位表 / 无调试目录 / 无 TLS / 无 .NET** | 易语言静态编译的典型产物 |

## 二、关键点：这是"静态编译"，不是旧版字节码

易语言有两种发布方式：

| 模式 | 产物 | 代码形态 | 能否用 ECodeExplorer |
|---|---|---|---|
| 独立编译 | exe + `krnln.fnr`（外部运行库） | 易语言字节码，运行时解释 | 可以（E 格式，`WTNE` 头） |
| **静态编译** | 单个 exe（本文件） | **编译器直接翻译成 x86 原生代码**，krnln 以静态库形式链入 | **不行** |

搜遍整个文件，`WTNE`（易语言 E 格式魔数）出现 **0 次**；而 `krnln` 字样也搜不到——因为运行时是以**目标代码**形式链进来的，不是以库文件/字节码形式。

这解释了两件事：

- `ecodeexplorer20` 打开这个 exe 会一无所获（它的配置里 `易格式特征码=WTNE`，正是为 2006 年的易语言 3/4 设计的）。**不要再在这条路上花时间。**
- 反过来是好消息：`.text` 里就是**真实的业务代码**，IDA/Ghidra 的 F5 能出有意义的伪代码（虽然运行时函数没有符号）。

## 三、文件结构解读

| 节区 | 大小 | 内容 |
|---|---|---|
| `.text` | 640 KB | krnln 运行时（大头）+ Ex_DirectUI + 启动器业务代码 |
| `.rdata` | 36 KB | 导入表、API 名字符串表、常量 |
| `.data` | 388 KB | **启动器常量池**（684 条字符串）+ 内嵌图片（8 张）+ 全局变量 |
| `.rsrc` | 44 KB | 图标（100×100）、版本信息、MANIFEST |

> 一个很实用的巧合：除 `.rsrc` 外，所有节区的 **文件偏移 == RVA**。
> 所以 **VA = 0x400000 + 文件偏移**。
> 例：`正版登录` 在文件偏移 `0x0B9E1B` → IDA 里按 `G` 跳 `0x4B9E1B` 就能看到引用它的代码。

## 四、要用 IDA / x32dbg 继续逆，怎么下手

### 1. 从字符串反查代码（最快）

在 IDA 里打开原 exe（不要用 raw 切片，直接开 PE），跳到下列 VA 并按 `X` 看交叉引用：

| 字符串 | 文件偏移 | IDA 地址 (VA) |
|---|---|---|
| `https://authserver.mojang.com/authenticate` | 0x0BA461 | 0x4BA461 |
| `正版登录` | 0x0B9E1B | 0x4B9E1B |
| `发现MCLauncher新版本` | 0x0FC240 | 0x4FC240 |
| `-Djava.library.path=` 段 | 0x0BA262 | 0x4BA262 |
| `net.minecraft.client.Minecraft` | 0x0B9F45 | 0x4B9F45 |
| `mclauncher.cfg` | 0x0AA2B0 | 0x4AA2B0 |

### 2. 从 API 断点反查（最快拿到真实行为）

x32dbg / OllyDbg 载入后对这些导入下断，然后点界面按钮：

| API | 能抓到什么 |
|---|---|
| `CreateProcessA` | **完整 java 启动命令行**（第二个参数，最值钱） |
| `InternetOpenUrlA` / `HttpOpenRequestA` / `HttpSendRequestA` | 所有下载/接口 URL 与 POST 内容 |
| `RegSetValueExA` / `RegCreateKeyExA` | 写了哪些注册表（jarfile 关联、登录态） |
| `ShellExecuteA` | 打开的网页/目录 |
| `WritePrivateProfileStringA` | 写了 `mclauncher.cfg` 哪些键 |
| `GetProcAddress` + `IsWow64Process` | 32/64 位判断与 Java 下载分支 |

### 3. 代码形态提示

易语言静态编译的代码很"直白"，没有 C++ 的 STL/异常展开，典型形态是：

```
push  <字符串VA>        ; 例如 0x4B9E1B
call  <krnln 文本比较/赋值函数>
...
push  <参数>
push  <参数>
call  <导入函数>        ; InternetOpenUrlA 等
```

看到 `mov eax, [0x4xxxxx]`（取全局文本指针）后紧跟 `push eax`，基本就是在传易语言的"文本型"参数。
函数边界可以通过 `push ebp / mov ebp, esp` 和 `ret N` 识别；krnln 内部函数大量复用，不要试图逐个命名。

### 4. 不要做的事

- 不要试图找 `WTNE` / 不要用 ECodeExplorer / 不要用 UPX 脱壳机（没壳）。
- 不要用 PEiD 以外的方式判断编译器——PEiD 会报 `Microsoft Visual C++ 6.0` 之类，这是**链接器**信息，不代表语言。
